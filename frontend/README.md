# ATTRITION Election Lab (frontend)

A dedicated dashboard for `attrition.election` -- not the base bandit
engine (that's `app.py`'s Streamlit dashboard, a different surface). Talks
to `election_api.py` (FastAPI, at the repo root) over HTTP; no simulation
logic lives here.

Five views:

- **National overview** -- a real choropleth map of all 543 real
  constituencies by tipping point (actual India boundary polygons, see
  Data sources below -- not a scatter-plot stand-in), a margin-vs-tipping-
  point scatter, and a searchable/sortable table. Click a seat (map or
  table) to open it in the Constituency lab.
- **Constituency lab** -- pick a real seat, adjust the Level 1 campaign's
  contact-intensity sequence and `n_voters`, run it, and see the
  switched-fraction curve against that seat's real tipping point, the
  recomputed outcome, and Level 2's persona decisions. Switched-fraction
  magnitudes are capped at a real, cited ceiling (FINDINGS.md #41) --
  small numbers are the honest result, not a bug.
- **Strategist** -- the national campaign-strategist agent
  (`attrition/election/strategist.py`): pick a total budget and compare
  funding the cheapest real seats first (greedy) against spreading the
  same budget evenly across every seat within reach (FINDINGS.md #40).
- **Forecast** -- a genuinely separate capability from the persuasion
  mechanism above: a real, honestly-backtested uniform-national-swing
  election forecasting baseline (`attrition/election/forecast.py`),
  leave-one-state-out cross-validated on the real 2014->2019 transition
  (FINDINGS.md #42).
- **Calibration** -- the real 2014->2019 winner-vote-share-swing vs.
  tipping-point-requirement comparison from `scripts/
  calibrate_campaign_magnitudes.py` (FINDINGS.md #38).

## Run it

Two processes, from the repo root:

```bash
pip install -e ".[api]"          # fastapi, uvicorn, pydantic
uvicorn election_api:app --reload --port 8000
```

```bash
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

The API's CORS allowlist is `localhost:5173` only (dev, not a deployed
origin) -- see `election_api.py`.

## Data sources

- Election results: TCPD/LokDhaba (`attrition/election/lokdhaba.py`'s
  `SOURCE`).
- Constituency boundary polygons (the map): **DataMeet**
  (`datameet/maps`, India's open-mapping community) -- MIT-licensed repo,
  data itself CC BY 4.0 (attribution required; given in the map's own
  caption). Refetch with `scripts/fetch_constituency_boundaries.py`. The
  join between the two real sources (they spell some constituency names
  differently) lives in `attrition/election/geo.py`, whose module
  docstring documents every alias and the two real data bugs building
  this surfaced -- see FINDINGS.md #39.
- `/api/calibration` reads a static `attrition/data/calibration_2014_2019.json`,
  generated by `scripts/calibrate_campaign_magnitudes.py` (a live network
  fetch) rather than fetched on every request; regenerate it by re-running
  that script if you want fresher numbers.
- `/api/forecast` reads a second real checked-in snapshot,
  `attrition/data/tcpd_lokdhaba_ge_2014.json` (`scripts/
  fetch_election_data_historical.py`), and computes its backtest live
  (deterministic, cheap -- no live network fetch per request).
